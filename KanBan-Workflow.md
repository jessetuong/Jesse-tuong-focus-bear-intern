# Research & Learn:
- How Kanban boards work: visual board with columns representing workflow stages; cards (tasks/issues) move left to right as work progresses, makes work-in-progress and bottlenecks visible at a glance, instead of hiding status in people's heads or scattered docs
- Typical columns
1. Backlog / Not Started — work identified but not begun
2. In Progress — actively being worked on
3. Blocked — stalled on a dependency or decision
4. Ready for Review / In Review — done, awaiting feedback or approval
5. Done — completed and accepted
- How tasks move & who updates them
1. Whoever owns the task moves it — the person actively doing the work updates it as their status changes (not a manager doing it for them)
2. Movement happens as work actually changes state, not just at stand-up time, so the board reflects reality
- Benefits of limiting WIP
1. Forces finishing over starting — prevents everyone from having 5 half-done tasks
2. Surfaces bottlenecks faster (if "In Progress" is capped and full, you can't ignore a stuck task)
3. Reduces context-switching, which improves actual throughput and quality

# Reflection:
- Kanban manages priorities/avoids overload by making capacity visible — a full column is a visible signal to stop pulling in new work rather than silently overcommitting
- Workflow improvement: adopt a personal WIP limit such as allow only maximum 2 "in progress" tasks at once.
